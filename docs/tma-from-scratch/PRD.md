# PRD: Telegram Mini App «Заметки»

Версия 1.0 · MVP · документ для Claude Code

## 1. Цель и границы

Мини-приложение внутри Telegram для быстрых заметок с блочным редактором
в стиле Notion. Открывается из бота одним нажатием, без логина.
Главный экран — смартфон (320–430 px).

**Метрика успеха MVP:** пользователь открывает приложение, создаёт заметку
со списком и заголовком меньше чем за 10 секунд, и заметка гарантированно
сохраняется даже при плохой сети.

**Вне MVP:** совместный доступ, realtime, AI, полноценный офлайн,
вложения/изображения, таблицы, импорт .md, теги, архив.

## 2. Архитектура (решения уже приняты)

Один репозиторий, один деплой на Vercel.

| Слой | Технология |
|------|------------|
| Фронтенд | React 18 + Vite + TypeScript, Tailwind CSS |
| Редактор | BlockNote (`@blocknote/core`, `@blocknote/react`, `@blocknote/mantine`) |
| Telegram | Официальный скрипт `https://telegram.org/js/telegram-web-app.js` + свой тонкий хук-обёртка `useTelegram()` |
| Состояние/запросы | TanStack Query |
| Бэкенд | Hono в Vercel Functions (папка `api/`), Node runtime |
| Валидация initData | `@telegram-apps/init-data-node` (не писать HMAC вручную) |
| БД | Supabase Postgres. Доступ **только с сервера** по `SUPABASE_SERVICE_ROLE_KEY`. RLS включён, политик для `anon` нет (браузер в БД не ходит) |
| Миграции | SQL-файлы в `supabase/migrations/`, применяются вручную в SQL Editor |
| Валидация входных данных | zod |
| Тесты | Vitest (юнит + API), Playwright (смоук на мобильном вьюпорте) |

Почему так: минимум сервисов для новичка, секреты никогда не попадают в браузер,
одна ссылка для превью каждой ветки.

## 3. Переменные окружения

| Имя | Где | Назначение |
|-----|-----|-----------|
| `BOT_TOKEN` | только сервер | проверка подписи initData |
| `SUPABASE_URL` | только сервер | адрес проекта |
| `SUPABASE_SERVICE_ROLE_KEY` | только сервер | доступ к БД |
| `ALLOWED_ORIGIN` | только сервер | CORS (домен Vercel) |
| `DEV_AUTH_BYPASS` | только локально/превью | `1` — пускать фейкового пользователя вне Telegram. **Никогда** в продакшене |

Файл `.env.example` со всеми именами без значений — обязателен.

## 4. Функциональные требования

### FR-1. Авторизация через Telegram
- 1.1 Клиент берёт строку `Telegram.WebApp.initData` и шлёт её в каждом запросе:
  `Authorization: tma <initData>`.
- 1.2 Сервер проверяет подпись через `@telegram-apps/init-data-node`
  (`validate(initData, BOT_TOKEN, { expiresIn: 86400 })`). Ошибка → 401.
- 1.3 При первом успешном запросе создаётся пользователь (upsert по `telegram_id`).
- 1.4 `initDataUnsafe` используется только для отображения (имя, язык),
  никогда для доступа к данным.
- 1.5 Вне Telegram (обычный браузер) без `DEV_AUTH_BYPASS` показывается экран
  «Откройте приложение в Telegram» со ссылкой на бота.

### FR-2. Список и организация
- 2.1 Список заметок: заголовок (или «Без названия»), превью 1–2 строки
  обычным текстом, относительная дата изменения («5 мин назад», «вчера», «12 мар»).
- 2.2 Закреплённые заметки — отдельной секцией сверху.
- 2.3 Сортировка: по изменению (по умолчанию) / по названию. Выбор запоминается.
- 2.4 Папки, один уровень: создать, переименовать, удалить
  (заметки из удалённой папки переезжают в «Все заметки», не удаляются).
  Фильтр списка по папке — горизонтальные «чипсы» над списком.
- 2.5 Переместить заметку в папку — из меню заметки.
- 2.6 Поиск по заголовку и тексту, debounce 300 мс, подсветка совпадения в превью.
  Серверный: Postgres full-text (`tsvector`, конфигурация `simple`, чтобы работали
  и русский, и английский) + запасной `ILIKE` для коротких запросов.
- 2.7 Удаление → корзина (soft delete). В корзине: восстановить, удалить навсегда,
  «Очистить корзину». Записи старше 30 дней удаляются (Vercel Cron раз в сутки).
- 2.8 Свайп влево по заметке в списке — «Удалить»; long-press — меню
  (закрепить, папка, удалить).
- 2.9 Пагинация курсором по 30 заметок, подгрузка при скролле.

### FR-3. Редактор (стиль Notion)
- 3.1 Заголовок заметки — первая строка-заголовок над блоками
  (как в Notion), отдельное поле `title`.
- 3.2 Блоки: абзац, H1–H3, маркированный, нумерованный, чек-лист, цитата,
  код, разделитель. Ссылки — инлайн.
- 3.3 Слэш-меню «/» на русском: «Текст», «Заголовок 1», «Список», «Чек-лист» и т. д.,
  с поиском и по русским, и по английским названиям.
- 3.4 Markdown-шорткаты при вводе: `# `, `## `, `### `, `- `, `1. `, `[] `, `> `, ` ``` `,
  `**жирный**`, `*курсив*`, `` `код` ``, `---`.
- 3.5 **Мобильная панель над клавиатурой** (заменяет всплывающее меню BlockNote
  на телефоне): «+ блок» (открывает то же меню, что «/»), Ж, К, З, код, ссылка,
  чек-лист, отступ ←/→, скрыть клавиатуру. Прилипает к верху клавиатуры
  (через `visualViewport`), прокручивается по горизонтали, не перекрывает курсор.
- 3.6 Перемещение блоков: на десктопе — ручка ⋮⋮; на телефоне — в меню блока
  пункты «Вверх / Вниз» (drag на тач-экране BlockNote работает ненадёжно).
- 3.7 Undo/Redo (встроено в BlockNote; на мобильной панели — кнопки).
- 3.8 Автосохранение: debounce 1 с после последней правки + немедленно при
  `visibilitychange=hidden`, закрытии и выходе по BackButton.
  Индикатор в шапке: «Сохраняется…» / «Сохранено» / «Нет сети — сохранено на устройстве».
- 3.9 **Источник правды — `content_json` (блоки BlockNote).** `content_md`
  генерируется на клиенте из блоков при сохранении и используется для поиска,
  превью и экспорта. `content_text` (плоский текст) — для превью.
- 3.10 Экспорт: «Скопировать как Markdown», «Скачать .md»
  (через `Telegram.WebApp.downloadFile`, если доступен, иначе blob),
  «Поделиться» — `switchInlineQuery`/ссылка `https://t.me/share/url?text=...`.
- 3.11 Новая заметка открывается сразу в редакторе с фокусом и открытой клавиатурой.
  Пустая заметка без изменений при выходе удаляется.

### FR-4. Интерфейс и Telegram-интеграция
- 4.1 Экраны: Список (главный) → Редактор; Папки; Корзина; Настройки
  (сортировка, размер шрифта S/M/L, «О приложении»).
- 4.2 Стиль: много воздуха, без рамок и теней, системный шрифт
  (`-apple-system, Roboto, Inter`), один акцентный цвет = `button_color` из темы
  Telegram. Скругления 12 px. Иконки — lucide-react.
- 4.3 Все цвета — CSS-переменные из `Telegram.WebApp.themeParams`
  (`bg_color`, `text_color`, `hint_color`, `secondary_bg_color`,
  `section_bg_color`, `link_color`, `button_color`, `destructive_text_color`),
  обновляются по событию `themeChanged`. Цвета шапки/фона — `setHeaderColor`,
  `setBackgroundColor`.
- 4.4 При старте: `ready()` после первого рендера, `expand()`,
  `disableVerticalSwipes()` (чтобы свайп вниз в редакторе не закрывал приложение),
  `enableClosingConfirmation()` пока есть несохранённые изменения.
- 4.5 Навигация: нативная `BackButton` Telegram на всех экранах кроме списка.
  Кнопка «+» — плавающая (FAB) справа снизу на списке.
- 4.6 Отступы: `safeAreaInset` и `contentSafeAreaInset` Telegram + `env(safe-area-inset-*)`.
  Высота — `viewportStableHeight`, клавиатура — `visualViewport`.
- 4.7 Haptic: `impactOccurred('light')` на создание, `notificationOccurred('success')`
  на восстановление, `('warning')` на удаление навсегда.
- 4.8 Пустые состояния (нет заметок, ничего не найдено, пустая корзина)
  с одной строкой текста и действием. Скелетоны вместо спиннеров.
- 4.9 Удаление — с тостом «Заметка в корзине · Отменить» (5 с).
- 4.10 Язык — русский; все строки в одном файле `src/i18n/ru.ts`.
- 4.11 Десктоп Telegram: контент по центру, max-width 720 px.

### FR-5. Данные

```sql
users   (id uuid pk, telegram_id bigint unique not null, first_name text,
         username text, language_code text, created_at timestamptz default now())
folders (id uuid pk, user_id uuid fk → users on delete cascade, name text not null,
         position int, created_at timestamptz default now())
notes   (id uuid pk, user_id uuid fk, folder_id uuid null fk → folders on delete set null,
         title text default '', content_json jsonb, content_md text default '',
         content_text text default '', pinned boolean default false,
         deleted_at timestamptz null, created_at timestamptz default now(),
         updated_at timestamptz default now(),
         search tsvector generated always as
           (to_tsvector('simple', coalesce(title,'') || ' ' || coalesce(content_text,''))) stored)
```
Индексы: `notes(user_id, deleted_at, pinned, updated_at desc)`, GIN по `search`.
Каждый запрос на сервере фильтруется по `user_id` из проверенной сессии.
`id` заметки генерирует клиент (uuid) — это позволяет создавать заметку
мгновенно и офлайн.

### FR-6. API (REST, JSON, `/api/*`)

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/me` | текущий пользователь (создаёт при первом входе) |
| GET | `/api/notes?folder=&q=&sort=&cursor=&trash=0\|1` | список |
| PUT | `/api/notes/:id` | создать или обновить (upsert), тело включает `updated_at` клиента |
| GET | `/api/notes/:id` | одна заметка |
| DELETE | `/api/notes/:id` | в корзину; `?hard=1` — навсегда (только из корзины) |
| POST | `/api/notes/:id/restore` | восстановить |
| DELETE | `/api/trash` | очистить корзину |
| GET/POST | `/api/folders` | список / создать |
| PATCH/DELETE | `/api/folders/:id` | переименовать / удалить |
| GET | `/api/cron/purge` | очистка корзины >30 дней (защищён `CRON_SECRET`) |

Ошибки: `{ error: { code, message } }`. Тела валидируются zod.
Лимит размера тела заметки — 1 МБ.

## 5. Нефункциональные требования
- **Сохранность данных (главное).** Каждая правка сначала пишется в локальную
  очередь (IndexedDB через `idb-keyval`, ключ — id заметки), затем отправляется.
  При ошибке сети — повтор с экспоненциальной задержкой и при событии `online`.
  Конфликты — last-write-wins по `updated_at`.
- **Скорость.** Список открывается < 1,5 с на 4G: показываем кэш сразу,
  обновляем в фоне. Редактор BlockNote грузится лениво (`React.lazy`).
  Бандл начального экрана < 250 КБ gzip.
- **Безопасность.** Только HTTPS; CORS только `ALLOWED_ORIGIN`;
  rate limit 60 запросов/мин на пользователя; секреты только в env;
  ссылки в заметках открываются через `Telegram.WebApp.openLink`;
  никакого `dangerouslySetInnerHTML` с пользовательским контентом.
- **Доступность.** Тач-цели ≥ 44 px, контраст по теме Telegram, `aria-label` у иконок.
- **Качество.** `npm run typecheck`, `npm run lint`, `npm test` — зелёные перед каждым мерджем.

## 6. Критерии приёмки MVP
1. Открытие из бота в Telegram на iOS и Android без логина; два разных аккаунта
   не видят заметки друг друга; запрос с подделанным initData получает 401.
2. Создание, редактирование, автосохранение, удаление, восстановление заметки.
   Режим самолёта во время правки → после возврата сети изменения на сервере.
3. Слэш-меню, Markdown-шорткаты и мобильная панель работают на iOS и Android;
   клавиатура не перекрывает строку ввода.
4. Папки, закрепление, сортировка и поиск (рус/англ) работают.
5. Светлая и тёмная темы Telegram применяются на лету.
6. Экспорт в .md и «Поделиться» работают.

## 7. Этапы реализации
0. Каркас проекта, CLAUDE.md, линтеры, тесты, деплой «Hello» на Vercel.
1. Telegram-оболочка: тема, safe area, BackButton, навигация, моковые данные.
2. БД + авторизация initData + API заметок (с тестами).
3. Список и CRUD на реальном API, автосохранение и локальная очередь.
4. Редактор BlockNote: блоки, «/», шорткаты, мобильная панель, экспорт.
5. Папки, закрепление, поиск, корзина + cron.
6. Полировка: haptics, пустые состояния, скелетоны, проверка на устройствах.
