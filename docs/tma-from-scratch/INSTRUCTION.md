# Инструкция: Telegram Mini App «Заметки» с нуля с помощью Claude Code

Порядок действий для новичка. Ваша роль — продакт: ставите задачу,
проверяете результат на телефоне, принимаете или просите исправить.
Код пишет Claude Code.

Время: 6–7 сессий по 1–2 часа (по одной на этап).

---

## Шаг 1. Аккаунты (15 минут, один раз)

Нужны бесплатные аккаунты:
- **GitHub** — хранит код (уже есть).
- **Vercel** (vercel.com) — публикует приложение. Входите через GitHub.
- **Supabase** (supabase.com) — база данных. Входите через GitHub.
- **Telegram** — для бота.

## Шаг 2. Бот в Telegram (5 минут)

1. Откройте **@BotFather** → `/newbot` → придумайте имя и username (на `bot`).
2. BotFather пришлёт **токен** вида `123456:ABC...`. Это пароль от бота:
   никому не показывайте и **не вставляйте в чат с Claude**.
   Сохраните в менеджер паролей.

## Шаг 3. Новый репозиторий (5 минут)

1. GitHub → **New repository** → имя, например `tma-notes`, Private,
   галочка **Add a README**.
2. Положите в него два файла из этой папки:
   `PRD.md` и `CLAUDE.md` (GitHub → **Add file → Create new file**,
   вставьте текст, **Commit**).
3. Убедитесь, что у приложения Claude на GitHub есть доступ к новому репозиторию:
   github.com/apps/claude → Configure → добавьте `tma-notes`.

## Шаг 4. Облачная среда Claude Code (5 минут)

Среда **tmanotes** уже создана: устанавливает зависимости при старте,
пускает в сеть к npm, Telegram и Claude API.
1. claude.ai/code → новая сессия → выберите репозиторий `tma-notes`
   и среду **tmanotes**.
2. После шага 5 попросите Claude: «Добавь в среду хост моего Supabase
   `xxxx.supabase.co`» — он предложит изменение, вы подтвердите.

## Шаг 5. Проект Supabase (10 минут)

1. supabase.com → **New project** → регион ближе к пользователям
   (Frankfurt), придумайте пароль БД, сохраните его.
2. **Project Settings → API**: скопируйте в менеджер паролей
   **Project URL** и ключ **service_role** (секретный!).
3. Таблицы создадите на этапе 2: Claude напишет SQL-файл, вы вставите его в
   **SQL Editor → Run**.

## Шаг 6. Разработка по этапам

### Ритуал каждого этапа
1. Новая сессия Claude Code (репозиторий `tma-notes`, среда `tmanotes`).
2. Вставьте промпт этапа (ниже).
3. Claude пришлёт план — прочитайте, задайте вопросы, напишите «ок».
4. Когда закончит: попросите **«Создай Pull Request»**.
5. Vercel сам соберёт превью-ссылку для PR — откройте её в Telegram (шаг 7)
   и проверьте по чек-листу этапа.
6. Нашли проблему — опишите в той же сессии **что сделали → что ожидали → что
   увидели**, лучше со скриншотом.
7. Всё хорошо → **Merge** PR на GitHub. Следующий этап — в новой сессии.

> Правило: один этап — одна сессия — один PR. Так проще проверять
> и откатывать.

### Этап 0 — каркас
```
Прочитай PRD.md и CLAUDE.md. Выполни этап 0: создай проект на Vite + React +
TypeScript + Tailwind, папку api/ с Hono для Vercel Functions, настрой ESLint,
Prettier, Vitest, скрипты typecheck/lint/test, .env.example, vercel.json.
Главная страница — «Привет, Telegram», эндпоинт /api/health отвечает {ok:true}.
Сначала покажи план.
```
После мерджа — **подключите Vercel** (один раз):
1. vercel.com → **Add New → Project** → импорт `tma-notes` → **Deploy**.
2. **Settings → Environment Variables**: `BOT_TOKEN`, `SUPABASE_URL`,
   `SUPABASE_SERVICE_ROLE_KEY`, `ALLOWED_ORIGIN` (ваш адрес `https://….vercel.app`),
   `CRON_SECRET` (любая длинная случайная строка). Для окружения **Preview**
   добавьте ещё `DEV_AUTH_BYPASS=1`, для **Production** — не добавляйте.
3. **Settings → Deployment Protection** → выключите **Vercel Authentication**
   для Preview, иначе Telegram не откроет превью-ссылки.
4. **Deployments → Redeploy**, чтобы переменные применились.

✅ Проверка: адрес `https://….vercel.app` открывается, `/api/health` → `{"ok":true}`.

### Этап 1 — Telegram-оболочка

BackButton, роутинг экранов Список/Редактор/Папки/Корзина/Настройки,
FAB «+». Данные пока моковые. Добавь отладочную консоль eruda, которая
включается по ?debug=1. Сначала план.
```
✅ Проверка в Telegram: тема совпадает со светлой/тёмной темой Telegram;
кнопка «Назад» Telegram работает; ничего не залезает под «чёлку»
и нижнюю полосу.

### Этап 2 — база, авторизация, API
```
Выполни этап 2 из PRD.md: SQL-миграция по FR-5, проверка initData по FR-1,
API по FR-6 (кроме cron), zod-валидация, rate limit, CORS. Напиши тесты:

В конце скажи, какой SQL мне выполнить в Supabase.

✅ Проверка: тесты зелёные (Claude покажет вывод); в Supabase →
**Table Editor** после открытия приложения появился ваш пользователь.

### Этап 3 — список и автосохранение
```
Выполни этап 3 из PRD.md: список заметок на реальном API (FR-2.1, 2.2, 2.9),
создание/удаление/восстановление, автосохранение FR-3.8 и локальная очередь
из раздела 5 (IndexedDB, повторы, last-write-wins). Редактор пока простое
textarea. Сначала план.
```
✅ Проверка: создать заметку, закрыть приложение, открыть — она на месте.
Включить режим самолёта, напечатать текст, выйти, выключить режим самолёта,
открыть — текст сохранился. Открыть с компьютера (Telegram Desktop) —
те же заметки.

### Этап 4 — редактор

Выполни этап 4 из PRD.md: BlockNote вместо textarea (FR-3.1–3.7, 3.9–3.11),

### Этап 5 — папки, поиск, корзина

Выполни этап 5 из PRD.md: папки FR-2.4–2.5, закрепление, сортировка,

```
✅ Проверка: поиск находит по русскому и английскому слову из середины текста;

Выполни этап 6 из PRD.md: haptics FR-4.7, пустые состояния и скелетоны FR-4.8,

из раздела 6 PRD и напиши, что проверено автоматически, а что нужно
проверить мне руками на телефоне.
```

## Шаг 7. Подключить приложение к боту

1. **@BotFather** → `/mybots` → ваш бот → **Bot Settings → Configure Mini App →
   Enable Mini App** → вставьте адрес `https://….vercel.app`.
2. Там же можно задать кнопку меню: **Menu Button** → тот же адрес.
3. Откройте бота в Telegram на телефоне → кнопка меню → приложение.
4. Для проверки превью-ссылки PR: отправьте ссылку себе в «Избранное»
   и откройте — или временно поставьте её в Menu Button.

## Шаг 8. Если что-то не работает

- **Белый экран / ошибка в Telegram** — откройте приложение с `?debug=1`
  в конце адреса: появится консоль eruda. Скриншот ошибки — Claude.
- **Ошибка 401** — проверьте `BOT_TOKEN` в Vercel (без пробелов),
  сделайте Redeploy.
- **Данные не сохраняются** — Supabase → **Logs**, Vercel → **Logs**:
  скопируйте красные строки Claude (без токенов).
- **Claude сделал не то** — не правьте код сами: напишите, что не так,
  и попросите исправить. Если совсем запуталось — закройте PR без мерджа
  и начните этап заново в новой сессии.

## Безопасность — коротко
- Токен бота, service_role ключ, пароль БД — только в Vercel Environment
  Variables и менеджере паролей. Никогда в чат и в код.
- Если секрет утёк: BotFather → `/revoke` (новый токен бота);
  Supabase → **API → Roll** service_role ключ. Обновите их в Vercel.
- `DEV_AUTH_BYPASS=1` — только для Preview, никогда для Production.
